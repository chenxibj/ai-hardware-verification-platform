# ADR-002: 数据库选择 PostgreSQL + TimescaleDB

## 状态

已采纳 (Accepted)

## 背景

AI 软硬件验证平台的数据存储需求包括：

- **关系型数据：** 用户、设备、评测计划、任务、评测模板等实体及其复杂关联关系
- **时序数据：** 评测过程中产生的性能指标（吞吐量、延迟、功耗、温度等）随时间变化的数据
- **JSON 半结构化数据：** 不同芯片/算子/模型的评测参数和结果格式各异
- **聚合分析：** 多维度对比分析、趋势分析、基线对比
- **数据量预估：** 单次评测产生数千至数万条指标数据点；平台长期运行后预计数亿条时序记录

当前部署使用 PostgreSQL 15（docker-compose 中定义），Flyway 管理 schema 迁移。

## 决策

选择 **PostgreSQL 15** 作为主数据库，规划引入 **TimescaleDB** 扩展处理时序数据。

## 理由

### 1. PostgreSQL 作为关系型数据库的优势

- **JSONB 支持：** 原生 JSON 存储和查询，适合半结构化的评测参数/结果
- **丰富的数据类型：** Array、UUID、INET、Range 等，减少应用层转换
- **全文搜索：** 内置 tsvector，设备/模型搜索无需额外 ES
- **窗口函数与 CTE：** 复杂分析查询（排名、趋势、环比）原生支持
- **MVCC 并发控制：** 读写不互斥，评测结果写入不阻塞查询

### 2. TimescaleDB 扩展的互补价值

- **无缝集成：** 作为 PostgreSQL 扩展，无需独立部署和运维额外系统
- **自动分区：** 基于时间的 hypertable 自动分片，解决大表查询性能问题
- **连续聚合：** 内置物化视图自动刷新，支持按分钟/小时/天的预聚合
- **数据保留策略：** 自动过期旧数据，控制存储成本
- **标准 SQL：** 使用标准 SQL 即可查询，与 JPA/Spring Data 无缝对接

### 3. 统一技术栈降低运维复杂度

- 一套数据库同时满足 OLTP 和时序分析，减少跨系统数据同步
- 统一备份恢复策略、统一监控、统一连接池管理
- 团队只需掌握 PostgreSQL 即可

### 4. Spring 生态原生支持

- Spring Data JPA + PostgreSQL 是最成熟的组合之一
- Flyway 完美支持 PostgreSQL DDL 迁移
- HikariCP 连接池对 PostgreSQL 优化良好

## 后果

### 正面

- 开发体验统一：所有数据操作使用相同的 SQL/JPA 接口
- 运维简单：单一数据库进程，Docker 部署即可
- 扩展灵活：后续可通过 Citus 实现水平分片
- 成本可控：开源免费，无厂商锁定

### 负面

- 单机 PostgreSQL 在超大规模时序写入场景（>100 万条/秒）可能需要分片
- 复杂分析查询在数据量极大时可能需要额外优化（分区裁剪、并行查询调优）
- TimescaleDB 扩展需要特定版本的 PostgreSQL 镜像

## 替代方案

### ClickHouse

- **优势：** 列式存储，超大规模分析查询性能极强（数十亿行秒级响应）；向量化执行引擎
- **放弃原因：** 
  - 不适合 OLTP 场景（更新/删除开销大）
  - 不支持事务，无法作为主库
  - 需要独立部署和维护，增加架构复杂度
  - 实时写入需要批量 buffer，与逐条结果上报模式不匹配
- **未来可能：** 如数据量增长到 TB 级，可考虑作为冷数据分析层引入

### InfluxDB

- **优势：** 专为时序设计，写入性能极高；内置降采样和保留策略
- **放弃原因：**
  - 仅支持时序场景，仍需关系型数据库存主业务数据
  - InfluxQL/Flux 查询语言有学习成本，与 JPA 不兼容
  - 开源版本（OSS）功能限制，集群需商业授权
  - 额外维护一套独立系统，运维成本翻倍

### MySQL

- **优势：** 国内使用最广泛，团队普遍熟悉
- **放弃原因：**
  - JSON 支持弱于 PostgreSQL（无 JSONB 索引）
  - 窗口函数支持较晚，复杂分析能力不足
  - 无时序扩展可用
  - 全文搜索能力弱

### MongoDB

- **优势：** 灵活的文档模型，适合半结构化数据
- **放弃原因：**
  - 不适合强关联关系的业务模型
  - 事务支持不如关系型数据库成熟
  - 与 Spring Data JPA 不兼容，需要 Spring Data MongoDB
  - 缺乏成熟的时序分析能力
