# ADR-005: 对象存储选择 MinIO

## 状态

已采纳 (Accepted)

## 背景

AI 软硬件验证平台需要存储以下类型的非结构化数据：

- **评测产物：** 模型文件、编译产物、推理输出、日志文件
- **报告资源：** 生成的 PDF 报告、图表截图、对比分析图
- **上传文件：** 用户上传的模型权重、数据集、配置文件
- **评测脚本：** 各芯片/框架的评测脚本包
- **数据规模：** 单次评测产物数 MB 至数 GB，平台总量预计 TB 级

存储需求：S3 兼容 API、高可用、支持大文件上传、支持生命周期管理。

## 决策

选择 **MinIO** 作为对象存储方案，通过 Docker 自部署。

## 理由

### 1. 完全自主可控

- 开源（AGPL v3），无厂商锁定
- 数据完全存储在自有服务器，符合安全合规要求
- 验证平台涉及芯片性能数据，属于敏感信息，不宜放公有云

### 2. S3 API 100% 兼容

- MinIO 实现完整的 S3 API，应用层代码无需修改即可迁移
- Java SDK（minio-java 8.5.9）已在项目中使用，API 清晰
- 未来如需迁移至公有云 S3/OSS，仅需更改 endpoint 配置

### 3. 部署与运维极简

- 单 Docker 容器即可启动（docker-compose 中已定义）
- Web Console（:9001）提供 GUI 管理界面
- 与开发环境一致的生产部署模式，减少环境差异

### 4. 性能优秀

- 原生分布式架构，支持纠删码（Erasure Coding）
- 读写性能可线性扩展
- 适合大文件（模型权重 GB 级）的分片上传

### 5. 成本优势

- 开发/测试环境零成本
- 生产环境仅需磁盘成本，无 API 调用费用
- 相比云 OSS 的流量费用，内网访问完全免费

## 后果

### 正面

- 开发体验好：本地 docker-compose up 即可使用，无需申请云服务
- 数据安全：敏感评测数据不出内网
- 成本可预测：无按量计费，磁盘扩容即可
- 迁移灵活：S3 API 兼容意味着随时可切换到其他 S3 实现

### 负面

- 需要自行管理存储基础设施（磁盘、备份、容量规划）
- 高可用需要多节点部署（生产环境至少 4 节点 Erasure Coding）
- 缺少 CDN 加速能力（如需公网分发需额外方案）
- 没有云厂商的 SLA 保障

## 替代方案

### 阿里云 OSS

- **优势：** 全托管、高可用（11 个 9）、内置 CDN/图片处理/生命周期管理、无需运维
- **放弃原因：**
  - 评测数据涉及芯片厂商敏感信息，客户可能不接受公有云存储
  - API 调用和流量产生持续费用，数据量增长后成本不可控
  - 开发/测试环境也产生费用
  - 厂商锁定：OSS 私有 API 扩展不兼容标准 S3
- **折中方案：** 如后续需要公网分发（报告共享等），可配置 OSS 作为特定 Bucket 的后端，MinIO 保留核心数据

### AWS S3 / Azure Blob

- **优势：** 全球基础设施、极高可用性
- **放弃原因：** 国内访问延迟高、合规要求（数据出境）、成本高于国内方案

### Ceph (RGW)

- **优势：** 统一存储（块/文件/对象）、大规模验证
- **放弃原因：** 运维复杂度极高（Ceph 集群管理门槛高）、资源要求大（最少 3 OSD + Monitor）；对于 TB 级存储属于过度工程
